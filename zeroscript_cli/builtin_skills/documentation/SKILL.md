---
name: docs
description: Write or update developer documentation from verified project behavior.
argument-hint: [feature, command, or subsystem]
---
Document the implementation that exists, not the behavior you wish existed.

1. Inspect the actual entry points, options, defaults, limitations, and tests before writing.
2. Explain practical workflows with copyable commands and accurate paths.
3. Call out prerequisites, platform constraints, network/model requirements, and data/privacy implications when relevant.
4. Update the smallest appropriate set of docs and keep README, dedicated guides, and examples consistent.
5. Avoid marketing claims and do not describe tests as passing unless their output confirms it.
